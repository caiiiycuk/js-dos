# Proposal

## Why

Агенту нужен способ собирать и проверять DOS-бандл в той же локальной js-dos Studio, которую видит пользователь. Сейчас редактор управляется через UI, а подготовка самостоятельной страницы или приложения требует ручного копирования ресурсов и настройки запуска.

## What Changes

- Добавить Rust MCP-сервер в `mcp/` с транспортом stdio и готовыми бинарями в Releases для Linux, Windows и macOS. Для запуска нужны бинарь и установленный браузер, но не Node.js, Tauri или Playwright.
- Встроить собранные js-dos, Studio и ресурсы эмуляторов в бинарь. Открывать локальную Studio через HTTP на loopback, без перехода на публичный сайт и без обязательной загрузки с CDN.
- Добавить поддерживаемый API редактора js-dos. Агент и пользователь смогут работать с одним бандлом: создавать, загружать, менять конфигурацию и файлы, запускать, перезапускать и экспортировать результат в явно выбранную папку.
- Добавить простые проверки запуска и сценариев ввода, скриншоты и сообщения эмулятора. Для создаваемых проектов предоставлять проверку сборки и диагностику страницы.
- Генерировать самостоятельные проекты HTML, Vite, React, Vue и Angular. Копировать js-dos, CSS, JS/WASM эмуляторов и выбранный бандл рядом с проектом, а не ссылаться на `v8.js-dos.com`. Готовая страница не зависит от работающего MCP.
- Ограничить локальный канал управления и файловые операции. Не допускать незаметной перезаписи пользовательских файлов или правок из Studio.

## Capabilities

### New Capabilities

- `jsdos-mcp-runtime`: установка, локальная Studio из встроенных ресурсов, защищённое соединение с браузером и жизненный цикл MCP-сессии.
- `jsdos-studio-editing`: общий API редактора, итеративные правки бандла, согласование изменений и безопасный экспорт.
- `jsdos-project-generation`: самостоятельные проекты пяти видов с локальными ресурсами js-dos и корректным жизненным циклом плеера.
- `jsdos-diagnostics`: проверка бандла и запуска, сценарии ввода, скриншоты, сообщения эмулятора и диагностика созданных проектов.

### Modified Capabilities

Нет. На момент создания change команда `openspec list --specs --json` вернула пустой список.

## Impact

- Новая подпапка `mcp/` содержит Rust crate, браузерный канал управления, шаблоны, тесты и документацию установки. Node.js нужен для сборки встроенного UI разработчиком и для сборки проектов на фреймворках, но не для запуска release-бинаря.
- Дополнения затрагивают `src/public/types.ts`, создание `DosProps` в `src/main.tsx`, загрузку в `src/player-api-load.ts` и общие операции UI редактора. Особого внимания требуют применение конфигурации в `src/window/prerun-window.tsx`, экспорт в `src/frame/editor/editor-fs-frame.tsx` и пауза скрытой вкладки в `src/window/dos/dos-runtime.tsx`.
- Сборка ресурсов использует существующие Vite и пакет `emulators`. Rust-часть использует MCP SDK, асинхронный runtime и локальный HTTP/WebSocket. Точные версии фиксируются при реализации; новый движок эмуляции не создаётся.
- Добавляются проверки и release workflow в `.github/workflows/`. Существующие CDN-сборка, публичные значения по умолчанию js-dos и отдельный DOSBox-X debugger MCP сохраняются.
- В поставке и созданных проектах сохраняются лицензии js-dos и встроенных компонентов, а также сведения о соответствующих исходниках. Внешние sockdrive, игровые URL и сетевые сервисы не становятся автономными от одного копирования runtime.
