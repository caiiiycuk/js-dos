# Spec Delta

## Purpose

Позволить агенту и пользователю итеративно редактировать один DOS-бандл в локальной Studio и получать согласованный переносимый результат.

## ADDED Requirements

### Requirement: Создание и открытие бандла

Studio SHALL поддерживать создание нового бандла с конфигурацией, открытие локального `.jsdos` или ZIP и импорт локальной папки с файлами DOS-программы. Состояние SHALL показывать активный бандл, конфигурацию редактора, готовность эмулятора и ревизию правок. Некорректный вход MUST давать ошибку до замены текущего бандла; замена несохранённых правок SHALL требовать явного разрешения на их отбрасывание.

#### Scenario: Создание из локальной папки
- **WHEN** агент выбирает папку DOS-программы и задаёт конфигурацию запуска
- **THEN** Studio открывает бандл с относительными путями файлов и показывает конфигурацию пользователю

#### Scenario: Повреждённый архив
- **WHEN** агент открывает файл, который нельзя прочитать как поддерживаемый бандл
- **THEN** операция возвращает причину отказа, а предыдущий бандл и его правки остаются доступны

### Requirement: Общий поддерживаемый API редактора

js-dos SHALL предоставлять API для открытия бандла, чтения состояния и конфигурации, изменения конфигурации, файловых операций, запуска, перезапуска и получения полного снимка бандла. UI и MCP SHALL использовать общую реализацию изменяющих операций. API MUST NOT требовать доступа к внутреннему Redux store, поиска DOM-элементов или имитации нажатий кнопок Studio.

#### Scenario: Правка конфигурации агентом видна пользователю
- **WHEN** агент меняет конфигурацию через API
- **THEN** редактор Studio показывает ту же конфигурацию, которая будет применена при следующем запуске

### Requirement: Файловые операции и готовность

Редактор SHALL предоставлять просмотр дерева, чтение, запись, импорт и удаление файлов бандла. Для операций с работающей файловой системой SHALL использоваться текущее содержимое эмулятора. Если необходимая файловая система ещё не готова, операция MUST возвращать состояние готовности, а не скрытно запускать DOS-программу. Изменяющие операции SHALL выполняться последовательно и сообщать о частичном выполнении, если пакетная операция прервалась.

#### Scenario: Итеративное изменение файла
- **WHEN** агент записал файл в готовую файловую систему и затем прочитал его
- **THEN** он получает новое содержимое, а последующий полный экспорт содержит тот же файл

#### Scenario: Удаление до готовности файловой системы
- **WHEN** агент запрашивает удаление файла до готовности нужного состояния редактора
- **THEN** API возвращает ошибку состояния без неявного запуска и без сообщения об успешном удалении

### Requirement: Согласование правок пользователя и агента

Изменяющая команда агента SHALL указывать ожидаемую ревизию редактора. Правки пользователя SHALL обновлять ту же ревизию. При несовпадении ревизии команда MUST возвращать конфликт и актуальную ревизию без перезаписи новых пользовательских правок. API MUST NOT представлять ревизию редактора как журнал всех записей самой DOS-программы.

#### Scenario: Пользователь успел изменить конфигурацию
- **WHEN** пользователь изменил конфигурацию после чтения состояния агентом, а агент отправил правку со старой ревизией
- **THEN** правка агента отклоняется, и конфигурация пользователя сохраняется

### Requirement: Запуск и перезапуск с актуальной конфигурацией

Запуск SHALL применять текущую конфигурацию редактора. Перезапуск SHALL сохранять текущие файлы и применять новые настройки без потери правок. Состояние SHALL различать конфигурацию редактора и уже запущенную конфигурацию. Ошибка запуска MUST содержать причину и не считаться готовностью эмулятора.

#### Scenario: Настройки изменены во время работы
- **WHEN** агент изменил конфигурацию запущенного бандла и запросил перезапуск
- **THEN** новый запуск использует изменённую конфигурацию и последние файлы бандла

### Requirement: Полный согласованный экспорт

По запросу пользователя сервер SHALL записывать полный `.jsdos` в указанную папку и возвращать фактический путь. Архив SHALL включать последние файлы, `.jsdos/dosbox.conf` и конфигурацию js-dos из редактора, даже если настройки ещё не применялись к запущенному эмулятору. Снимок MUST быть согласован с указанной ревизией. Экспорт SHALL отличаться от сохранения только changes и SHALL явно сообщать о внешних зависимостях, включая sockdrive.

#### Scenario: Экспорт до перезапуска
- **WHEN** пользователь поменял настройки после запуска, а затем запросил экспорт
- **THEN** экспортированный архив содержит новые настройки редактора и текущие файлы, а не только changes или старую конфигурацию

#### Scenario: Назначение уже существует или запись прервалась
- **WHEN** файл назначения существует без явного разрешения на замену либо запись завершается ошибкой
- **THEN** сервер возвращает ошибку и сохраняет предыдущий файл назначения без частичного содержимого

#### Scenario: Бандл использует удалённый диск
- **WHEN** экспортируется бандл с внешним sockdrive
- **THEN** результат сообщает об оставшейся сетевой зависимости и не объявляет архив полностью автономным
